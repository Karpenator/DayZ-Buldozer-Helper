# Канал Terrain Builder ↔ Buldozer: что уже известно
> **Статус:** сообщения разобраны по живым дампам и достоверны (см. `HANDOFF.md`,
> там новее). Транспорт — НЕ named pipe с именем `<токен>,8EDB`, как тут
> предполагалось: имя канала не наблюдалось ни разу. Канал и его второй конец
> устанавливаются командой `handle_names.py`.


Записки по разведке. Всё, что ниже, выведено из живого захвата (`frida_capture.py`) и
разбора дампов (`messages.py`, `analyze_dump.py`). Ничего не выдумано: непроверенное
помечено словом **гипотеза**.

## Как устроен канал

* Terrain Builder дописывает движку параметр `-connect=pipe\<токен>,8EDB`; `<токен>` —
  шестнадцатеричное число, `8EDB` во всех наблюдениях одинаково.
* Канал — обычный именованный канал Windows (`\\.\pipe\...`), данные **не шифруются**:
  в потоке видны открытым текстом пути моделей и слоёв.
* Обмен идёт **сообщениями**, а не потоком байт. Сообщение начинается с 4-байтного кода
  (`u32`, little endian), дальше — данные, длина которых зависит от кода.
* Писатель отправляет одно сообщение за один вызов записи, поэтому в дампе по стороне
  записи (`tx`) границы записей = границы сообщений. По стороне чтения (`rx`) одна
  запись может содержать несколько сообщений — их склеивает канал.
* В сеансе участвуют как минимум **две пары каналов**: одна носит трансформы (записи по
  72 байта в обе стороны), вторая — «большие» данные (описание мира, слои, объекты).

## Что TB отправляет при подключении

Первый большой пакет (64 КБ за одну запись):

1. сообщение кода **2** — параметры мира;
2. сообщение кода **17**;
3. список **слоёв поверхности** — по одному на плитку, например
   `P:\evelone2666\data\layers\P_000-000_L01_L13.rvmat`,
   `P_000-001_L01_L13.rvmat`, … `P_001-000_L01_L13.rvmat` (индексы плитки `X-Y`);
4. «морской» слой `ca\desert\data\--sea--`;
5. дальше — большие однородные массивы (в хвосте пакета идёт повторяющееся значение
   `1.1291f`, **гипотеза**: маска/индексы слоёв или неинициализированный буфер).

Пути собираются из папки проекта TB (`P:\evelone2666\...`) — значит, клиент должен
уметь отдавать Buldozer те же пути: он читает `.rvmat` по этим путям сам.

## Что уходит во время работы

В захвате пользователя TB за ~260 с отправил **2530 сообщений кода 25** (по 76 байт):
`[25][1][00 00 00 05]` + матрица 4×4. У всех вращение единичное, а смещение —
координаты внутри карты (1287.0, 19.85, 935.96 и соседние), меняются примерно 10 раз в
секунду. **Гипотеза**: это трансформ курсора/кисти — TB показывает Buldozer'у, где
сейчас курсор и какой кистью он работает (курсор в Buldozer — отдельная модель, см. PMC
wiki). Модель под курсором шла отдельным сообщением кода 13 с путём
`dz\structures\military\houses\mil_barracks_round.p3d`.

Если гипотеза верна, для нашей задачи это хорошая новость: рельеф и объекты идут
отдельными, более крупными сообщениями, а частый поток — всего лишь положение курсора.

## Что Buldozer отправляет в TB

* Поток сообщений кода **6** по 72 байта, частота порядка 20–25 в секунду — это
  **трансформ камеры** (позиция меняется при движении в Buldozer: 1279 → 1297 → 1277 →
  1238 по X).
* Разбирается как матрица 4×4 (row-major), например:
  `[(-0.9867, 0.1047, 0.1245, 1279.35), (0, 0.7655, -0.6435, 19.63), (-0.1622, -0.6349, -0.7550, 1145.48), (0,0,0,0)]`.
* В той же стороне встречаются коды 5, 7, 8, 25, 28 — то есть обмен двусторонний и
  Buldozer не только отвечает камерой.

## Чего не хватает

1. **Вид этого пакета со стороны Buldozer** (что движок читает при подключении) — это
   и есть спецификация для нашего клиента. В первом захвате он не попал: TB при
   подключении запускает Buldozer заново, а старый агент остался в уже закрытом
   процессе. Лечится режимом `--watch dayz_x64` у `frida_capture.py`.
2. **Что уходит при правке рельефа и объекта** — нужен захват с одним поднятым холмом и
   одним сдвинутым объектом.
3. Коды 3, 4, 9–12, 14–16, 18–24, 26, 27 в захвате не встречались: их природа неизвестна.
4. Как передаются сами высоты рельефа: в первом пакете (64 КБ) их не видно — значит, они
   либо в отдельных сообщениях, которых не было в захвате (мир уже был загружен), либо в
   хвосте пакета (там длинный однородный массив `1.1291f`). **Эту часть обязательно
   проверить на захвате с правкой рельефа.**

## План

1. Захват с `--watch game` (см. README, этап 1) — получить обе стороны подключения.
2. Разобрать пакет мира до конца (слои, размеры, порядок) — `messages.py --writes
   --strings`.
3. Собрать в редакторе минимальный сервер канала: слушаем pipe, запускаем Buldozer с
   нашим `-connect=`, отвечаем на приветствие и отдаём описание мира.
4. Дальше по одному добавлять сообщения (камера, слои, объекты) до полной картинки.
