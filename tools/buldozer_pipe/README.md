# Свой канал Buldozer: разведка закрытого протокола TB

Задача: показывать правки редактора в Buldozer **сразу**, без перезапуска (на больших
картах перезапуск занимает десятки секунд — как режим обновления он не годится).

Это папка с инструментами разведки: сначала выясняем, что за канал у Terrain Builder с
Buldozer, затем повторяем его в редакторе.

## Обновить копию из архива без git

Копии инструментов устаревают. Признаки старой копии: `SyntaxWarning` про `\<` и `\p`
при запуске `probe_pipe.py` и **нет** строки `инструменты от <дата>` в начале вывода.
Проверить свежесть своей копии (git не нужен):

```powershell
py -3 tools\buldozer_pipe\frida_capture.py --list
```

Первая строка — `инструменты от 2026-10-12` (дата сборки): сверьте её с датой архива.

1. Скачать архив ветки `main` браузером (просто по ссылке, без git):
   <https://github.com/Karpenator/Dayz-World-Editor/archive/refs/heads/main.zip>
2. Распаковать в **новую** папку (не поверх старой — так старые файлы не смешаются с новыми).
3. Скопировать из старой папки свои записи: `captures\`, `probe_*.log`, `report*.txt` и
   другие `.log`/`.txt` с дампами — их нет в архиве, они нужны для разбора.
4. Проверить свежесть командой выше: строка `инструменты от <дата>` должна быть.
5. Работать из новой папки; старую удалить или оставить как резервную.

Если копий несколько (например, на `C:\…\Desktop\…` и `D:\temp\…`) — обновить **все**
или работать только из обновлённой. Никаких `git pull` не требуется.

## Что уже известно

**Короткая версия — в `PROTOCOL.md`** (коды сообщений, формат строк, что уходит при
подключении). Ниже — с чего всё началось.


| Факт | Откуда |
| --- | --- |
| TB дописывает движку параметр `-connect=pipe\<токен>,8EDB` | строки запуска в логах TB (форумы BI, 2014 — Arma 3: `C0926,8EDB`, `6078A,8EDB`; 2025 — DayZ: `1A041E,8EDB`) |
| **Имя канала из этого параметра никем не наблюдалось**: в живых дампах хэндлы канала безымянны, `tap` не находит `<токен>,8EDB` (ошибка 2), в перечислителе `\\.\pipe\` такого канала нет | захваты №1–№3 (см. `HANDOFF.md`); имя канала устанавливает `handle_names.py` |
| Вторая часть параметра (`8EDB`) во всех наблюдениях одна и та же | те же логи: похоже на «магию»/версию протокола, а не на случайное число |
| Канал — Windows named pipe (системный объект `\\.\pipe\...`) | формат параметра `pipe\...` |
| Публичных описаний протокола нет | проверил biki, форумы BI/DayZ, репозиторий BI `DayZ-Script-Diff`, GitHub code search — упоминаний формата сообщений нет |
| В скриптовом API DayZ **нет** функции, меняющей высоты рельефа | официальный `DayZ-Script-Diff`: у `World` только `SetBuldozerWaterEnabled`, `SetViewDistance` и т.п.; `setTerrainHeight` — это Arma 3 (SQF), в Enforce его нет |
| Сам Buldozer умеет кисти рельефа (`UABuldSetTerrainHeight`, `UABuldSmoothMod`, `UABuldFlattenMod`…) | biki «Buldozer for Terrain Builder»; значит движок правит высоты изнутри, и «горячий» рельеф существует — но доступен он только по каналу |
| Buldozer выполняет **наш** Enforce-скрипт (`P:\scripts\buldozer.c`, `BuldozerMain()`, F10) | biki; живой пример — проект [MaskOver](https://github.com/Mahauu/MaskOver): внешняя программа гоняет с Buldozer позицию курсора и состояние кисти через файлы в `$profile:` |
| Через скрипт можно читать/писать файлы, рисовать пометки (`Shape`), управлять камерой и дальностью, но не рельефом | исходники MaskOver (`buldozer.c`), `DayZ-Script-Diff` |

Вывод: «мгновенно, как в TB» = говорить по тому самому каналу. Всё остальное (файлы,
скрипты) рельеф не меняет.

## План разведки

Этапы идут по возрастанию усилий; каждый следующий нужен, только если предыдущий не дал
ответа. Все команды — из этой папки, Python 3.8+.

### Этап 0. Строки в бинарниках (2 минуты, ничего ставить не надо)

Возможные подсказки: имена сообщений, текст ошибок, константа `8EDB`.

```powershell
python strings_scan.py "E:\Steam\steamapps\common\DayZ\DayZ_x64.exe" --filter "buld|pipe|connect=|8EDB|terrain" --utf16 --out strings_dayz.txt
python strings_scan.py "<путь к TerrainBuilder.exe>" --filter "buld|pipe|connect=|8EDB|terrain" --utf16 --out strings_tb.txt
```

Прислать `strings_dayz.txt` и `strings_tb.txt` (это небольшие текстовые файлы).

### Этап 1. Запись живого канала (5 минут, `pip install frida-tools`)

**Самый ценный этап**: здесь видно и установку связи, и первичную передачу мира, и
мелкие правки. Захват нужно включать **до** нажатия «Connect to Buldozer»: первичная
передача мира уходит в первые секунды.

```powershell
python frida_capture.py --list                       # проверить имена процессов
# TB уже запущен; ждём появления Buldozer, которого TB создаёт сам при Connect:
python frida_capture.py --attach terrain --watch dayz_x64 --out captures
```

Дальше: в TB нажать «Connect to Buldozer» (если он уже подключён — сначала «Disconnect»,
чтобы связь переустановилась), дать миру загрузиться, **поднять один холм** кистью в TB,
**подвинуть один объект**, снова поднять холм. Остановить — `Ctrl+C`.

Что видно в выводе:

* `подключился: ... (PID ...)` — агент встал в процесс;
* `появился DayZ_x64.exe (PID ...) — подключаюсь` — TB запустил новый Buldozer, и мы
  подхватили его автоматически (это и есть режим `--watch`);
* `канал: \\.\pipe\XXXXXX,8EDB (CreateFileW)` — **вот он**: имя канала пойманo;
* `каналов: 0` в сводке означает, что именованных каналов пока не видели. Обычно это
  значит, что связь была установлена до запуска захвата: тогда перезапустите связь
  (Disconnect → Connect). Имена уже открытых дескрипторов агент всё равно разбирает
  сам (NtQueryObject) и печатает их как `канал: ...` — если имя мешает, есть
  `--no-resolve-names`.

⚠ Процесс игры: под Frida лучше запускать `DayZDiag_x64.exe` (без BattlEye). К розничному
`DayZ_x64.exe` подключаться не стоит, если вы играете на серверах.

Прислать `captures\capture_*.log` (можно zip: первичная передача карты бывает на десятки
мегабайт — это нормально и как раз интересно). Первая строка отчёта
(`python analyze_dump.py ...`) сразу говорит, пойман ли канал: «Канал найден: …» или
«Каналов с „8EDB“ нет…».

### Этап 2. Разбор записи (1 минута)

```powershell
python analyze_dump.py captures\capture_*.log --show 5 --out report.txt
```

Отчёт показывает: сколько потоков, как поток режется на сообщения (гипотезы фрейминга),
первые байты и числа. Прислать `report.txt` — по нему уже видно, есть ли длина перед
сообщением и как устроены «плитки» рельефа.

### Если Frida не видит Terrain Builder или DayZ

Симптом: `--list` показывает процессы, но в списке нет ни `TerrainBuilder.exe`, ни
`DayZ_x64.exe`/Buldozer, ни `steam.exe` — при этом их «потомки» (`steamwebhelper.exe`)
на месте. Так выглядит **запуск от администратора**: процессы с повышенными правами
невидимы для непривилегированной Frida (и в списке заодно нет системных служб вроде
Antimalware Service Executable).

Что делать (по порядку):

1. **Подключиться по PID** — Windows видит такие процессы всегда, и `--list` теперь
   показывает разницу:
   ```powershell
   python frida_capture.py --list                 # внизу: «Windows видит, а Frida — нет»
   python frida_capture.py --attach 12900         # PID из этого списка
   ```
   `--attach` принимает и имя, и часть имени (`--attach dayz`), и PID.
2. **Запустить консоль «от имени администратора»** — тогда Frida видит и внедряется в
   процессы с повышенными правами. В начале вывода есть строка «консоль от
   администратора: да/НЕТ».
3. **Для движка — `DayZDiag_x64.exe`.** Розничный `DayZ_x64.exe` защищён BattlEye, к
   нему Frida не подключится (ошибка «unable to inject»). Диагностический exe работает
   в режиме Buldozer так же: замените `.exe file path` в
   *Terrain Builder → Tools → Preferences → Buldozer* на `DayZDiag_x64.exe` на время
   опытов.
4. Если TB под перехватом падает — снимайте только движок (`--attach <PID DayZ>`): по
   нему видно и что TB присылает, и что движок отвечает.

### Этап 2б. Заглянуть в канал без Frida (2 минуты, ничего не устанавливаем)

Frida — не единственный путь. Канал виден системе как обычный объект, поэтому:

```powershell
# 1. Пока TB соединён с Buldozer — какие каналы есть и есть ли среди них наш
python probe_pipe.py pipes

# 2. Токен видно в командной строке движка (диспетчер задач → Details →
#    добавить столбец «Command line», либо PowerShell):
Get-CimInstance Win32_Process -Filter "Name='DayZ_x64.exe'" | Select ProcessId, CommandLine

# 3. Подключиться к каналу TB вторым клиентом и ТОЛЬКО читать
python probe_pipe.py tap --token 1A041E --seconds 30
```

Если `tap` что-то получил — это самый ценный дамп: тот же поток, что идёт в Buldozer,
и никакого внедрения в процессы. Если `tap` пишет «канал занят» — значит, сервер пускает
только один экземпляр, и тогда возвращаемся к Frida.

### Этап 3. Проба своего канала (5 минут)

Проверяем, кто в паре сервер, и что движок присылает первым. В `--launch` можно вставить
**строку TB целиком** — вместе с её чужим `-connect=pipe\F414A8,8EDB`: скрипт заменит
токен на свой (раньше чужой оставался, движок уходил в канал TB, а наш pipe был пуст).

```powershell
python probe_pipe.py listen --launch "E:\Steam\steamapps\common\DayZ\DayZ_x64.exe -buldozer -window -exThreads=0 -mod= -noAsserts -nologs -profiles=P:\Buldozer -cfg=P:\Buldozer\Buldozer.cfg -name=Buldozer" --seconds 180 --out P:\capture3\probe.log
```

Ждём 15–25 с (первый запуск грузится дольше). Успех — строки:

```
подключился!
[   0.12] принято     8 Б: 1d 00 00 00 05 00 00 00
```

(рукопожатие движка: `[29][5]`). Если за `--connect-timeout` (60 с по умолчанию) никто не
подключился, скрипт **печатает подсказку и завершается**, а не висит. Дальше по подсказке:
токен как у TB (`--token 1A2B3C`, 6 hex-знаков), `probe_pipe.py pipes --find 8EDB` — не
ушёл ли движок в канал TB, и что `-connect=` в строке запуска указывает на наш канал.
Разбор того, что приняли:

```powershell
py -3 tools\buldozer_pipe\messages.py P:\capture3\probe.log --writes --count 6 --hex 96
```

### Этап 4. Клиент в редакторе

Когда понятен фрейминг: пишем на Python минимальный сервер канала, который после
загрузки Buldozer **досылает только изменившиеся плитки рельефа и объекты** — то есть
ровно то, что делает TB. Схема: редактор поднимает канал → запускает Buldozer с
`-connect=pipe\<токен>,8EDB` → при правке рельефа шлёт патч → Buldozer перестраивает
геометрию без перезапуска.

## Транспорт установлен: анонимные паймы, не именованный канал

Именованного канала `\\.\\pipe\\<метка>,8EDB` **не существует** — параметр
`-connect=pipe\\<метка>,8EDB` в командной строке движка лишь метка. Реальный канал —
два `CreatePipe` в Terrain Builder, концы которых TB передаёт движку унаследованными
хэндлами (проверено tap-ом с верным токеном при живом соединении, перечислением и
обходом хэндлов). Процесс TB — `terrainBuilder.exe` (с маленькой буквы).

`handle_names.py` показывает хэндлы каналов и их второй конец (по объекту ядра;
имена — через `GetFileInformationByHandleEx`, не зависает на занятых каналах):

```powershell
py -3 tools\buldozer_pipe\handle_names.py --name terrain --name dayz --name build --out P:\capture3\handles.txt
py -3 tools\buldozer_pipe\handle_names.py --all --out P:\capture3\handles_all.txt   # все процессы
```

Сам канал «мы вместо TB» — `buldozer_channel.py`:

```powershell
# 1) вытащить эталон пакета мира (65 536 Б) — можно указать файл дампа
#    ИЛИ просто папку, инструмент сам найдёт дамп с миром:
#    (дамп рабочего сеанса TB <-> Buldozer лежит и в корне архива)
py -3 tools\buldozer_pipe\buldozer_channel.py extract-world --dump P:\capture3 --out P:\capture3\world.bin

# 2) запустить движок НА НАШЕМ канале и проверить связь:
py -3 tools\buldozer_pipe\buldozer_channel.py probe --exe "E:\Steam\steamapps\common\DayZ\DayZ_x64.exe" --world P:\capture3\world.bin --seconds 20 --out P:\capture3\channel.log
```

Успех: `принято: код 29, 8 Б` -> `отправил мир` -> поток `код 6` (камера ~30/с).
Дамп `channel.log` читают `analyze_dump.py`/`messages.py`.

## Что прислать обратно

1. `strings_dayz.txt`, `strings_tb.txt` — этап 0;
2. `captures\*.log` (zip) — этап 1;
3. `report.txt` — этап 2;
4. вывод `probe_pipe.py` — этап 3;
5. `handles.txt` (вывод `handle_names.py`) — имена каналов и второй конец.

Этого хватит, чтобы собрать клиент канала.

## Меры предосторожности

* Все инструменты **ничего не пишут** в папки игры и проекта; логи кладутся рядом со
  скриптами (`captures\`, `probe_*.log`).
* Перехват Frida — это отладка чужого процесса: нужен тот же пользователь, иногда права
  администратора. К розничному DayZ с BattlEye не подключайтесь (см. выше).
* Если TB не запускается под перехватом — сначала запишите только Buldozer, связь всё
  равно будет видна со стороны движка.
* Дампы могут быть большие. Не коммитьте их в git (папка игнорируется через `.gitignore`).
