# HANDOFF — контекст для следующих сеансов

Здесь собран контекст работы над «живым» каналом TB ↔ Buldozer, чтобы следующий сеанс
не тратил время на разведку заново. Краткая версия протокола — ниже, полные записи —
в `PROTOCOL.md` (там местами устаревшее: где расходится, верить **этому файлу**).

## Цель

Редактор **сам** держит канал с движком (`DayZ_x64.exe -buldozer`), чтобы правки
(объекты, рельеф) появлялись в **уже запущенном** Buldozer — без перезапуска.
Перезапуск предпросмотра пользователь **отверг** как решение; старый редактор (рельеф,
`.wrp`, предпросмотр перезапуском) удалён — теперь программа = стартовое окно
(`terrain_editor/launcher.py`) + окно поверх Buldozer. Старый код — в истории git.

## Что уже есть (в `main`)

* `tools/buldozer_pipe/` — инструменты разведки канала:
  `frida_capture.py` + `capture.js` (захват трафика Frida: `--attach`, `--watch`,
  `--watch-timeout`), `messages.py` (разбор дампа на сообщения), `analyze_dump.py`,
  `probe_pipe.py` (свой named pipe), `strings_scan.py`, `PROTOCOL.md`, `README.md`.
* Тесты — `TerrainEditorPy/tests/test_buldozer_pipe_tools.py` (pytest, без Windows:
  тестируются чистые функции).
* `TerrainEditorPy/terrain_editor/` — стартовое окно + окно поверх Buldozer; модели берутся
  из `TemplateLibs\*.tml` проекта (`templates.py`), превью кэшируются (`thumbcache.py`).
  «Горячего» канала пока нет.
* Разбор записей кода 28 (правки рельефа от движка) — есть; **зеркалить высоты в
  редакторе ещё надо**.

## Окно поверх Buldozer (сделано, в `main`)

* `terrain_editor/buldozer_overlay.py` (Qt) + `buldozer_bridge.py` + `winbuldozer.py` (без Qt),
  описание — `TerrainEditorPy/OVERLAY_BULDOZER.md`. F8 — окно поверх Buldozer, F9 — поставить
  модель под курсором, Shift+F9 — отменить.
* Мост как у MaskOver: блок в `P:\scripts\buldozer.c` (F10) пишет точку под курсором в
  `$profile:we_bridge_state.txt` и создаёт модели по `$profile:we_bridge_cmd.txt`
  (`CreateStaticObjectUsingP3D`). В проект TB объекты пока попадают **импортом** текстового
  файла (формат DayZ Editor, `objects.format_objects`).
* Следующий шаг для «сразу в TB»: захват канала, где в Buldozer объект ставится (V),
  двигается и удаляется (D); затем посредник в канале TB ↔ Buldozer. **На Windows ещё не
  проверено** — первым делом попросить пользователя: установить скрипт, F10, F8, F9 и прислать
  `.RPT` из `P:\Buldozer`, если «нет связи со скриптом».

## Объекты сразу в открытый TB — сделано без канала (мост v14)

Новые объекты попадают в открытый TB «броском» файла объектов в окно TB (`WM_DROPFILES`,
`terrain_editor/tblive.py`): TB импортирует его в активный слой и сам показывает объект в
Buldozer; скрипт моста (строка `V|…` → `VF|…`) подтверждает, что объект TB появился, и наша
копия убирается. Подробно — `OVERLAY_BULDOZER.md`, раздел «Сразу в открытый Terrain Builder».
Канал ниже остаётся путём для рельефа и правок существующих объектов.

## Протокол (итог двух живых захватов; новее, чем PROTOCOL.md)

* **Транспорт установлен (окончательно): анонимные пайпы + унаследованные хэндлы.**
  TB делает `CreatePipe` (два канала: TB->движок и движок->TB), запускает движок с
  параметром `-connect=pipe\\<метка>,8EDB` (проверено: он есть в командной строке
  живого движка) и передаёт концы каналов унаследованными хэндлами. Именованного
  канала `\\.\\pipe\\<метка>,8EDB` **не существует**: `tap` с верным токеном даёт ошибку 2
  при живом соединении, перечисление пустое, frida с рождения процесса не видит ни
  одного `CreateFileW` канала. Параметр `-connect=` — лишь метка. Подтверждено и
  обходом хэндлов (`handle_names.py`): каналы без имени, второй конец — у
  `terrainBuilder.exe` (имя процесса TB — **с маленькой буквы**, фильтр «dayz» его
  не ловит; ловится `--name terrain --name build`).
* Фрейминг (подтверждён дампами): сообщение = `[u32 код][данные]`, одна запись
  WriteFile = одно сообщение. Строки — `[u32 len][ascii]` + NUL (NUL **не входит** в длину).
* Движок говорит первым: `[29][5]` — 8 Б, рукопожатие. Проверка: в консоли probe
  должно появиться `принято 8 Б: 1d 00 00 00 05 00 00 00`.
* TB отвечает описанием мира — **65 536 Б** одной записью:
  заголовок `[2][28][128][128][1024][1024][40.0f][40.0f]` + подструктуры
  (`17`, `66`, `5272`, `9`, `98` — сверить с эталоном; в PROTOCOL.md код 17 (66 Б)
  содержит числа `5272, 0xCCCCCCCC, 0, 9, 98`) + 36 строк слоёв
  `P:\evelone2666\data\layers\P_%03d-%03d_L01_L13.rvmat` + `ca\desert\data\--sea--`.
* Коды:
  * `5` / `7` — пинги (4 Б, ~каждые 19 с);
  * `6` — камера (72 Б, движок → TB, ~23 раза/с);
  * `13` — объект: матрица 4×4 + `[u32]` + путь `.p3d` (136 Б);
  * `25` — курсор/кисть (76 Б, в **обе** стороны;
  * `8` — 76 Б, движок → TB, назначение неизвестно (в PROTOCOL.md ошибочно 72 Б);
  * `28` — рельеф (см. ниже).
* **Рельеф (код 28):** 728 Б = `[28][count]` + count × `(u32 x, u32 y, f32 высота,
  u32 aux)`. Идёт **только движок → TB**: Buldozer сообщает TB, что налепил кистью.
  В самом TB рельеф не правится («в TB нельзя менять ландшафт, только в бульдозере»),
  поэтому сообщения «TB → движок: новые высоты» **не существует**.

## Открытый вопрос: как отдать свои высоты в живой Buldozer

* (а) отправить такие же записи кода 28 **самим** — не проверено, но это первое,
  что надо попробовать (см. «Следующие шаги»);
* (б) мост `P:\scripts\buldozer.c` (Enforce) + одно нажатие F10 — так работает
  [MaskOver](https://github.com/Mahauu/MaskOver): внешняя программа гоняет состояние
  через файлы в `$profile:`. Автоматизировать **первое** F10 не удалось;
* (в) перезапуск предпросмотра — **только запасной вариант**.

Приём правок **от** живого Buldozer (28) у нас уже есть (захваты/разбор) — их надо
зеркалить в редакторе.

## Следующие шаги (главная работа)

1. **Прогнать `buldozer_channel.py probe` на машине пользователя** — мы вместо TB:
   два `CreatePipe`, запуск движка с унаследованными концами и `-connect=pipe\\<метка>,8EDB`,
   приём `[29][5]`, ответ пакетом мира 65 536 Б (вытащить `extract-world` из дампа
   пользователя или из эталона в корне репо). Успех = движок шлёт камеру (код 6) и
   показывает мир. Если рукопожатия нет — перебор вариантов передачи хэндлов
   (порядок концов, второй пары каналов, режим PIPE_READMODE_MESSAGE) по логам.
2. **Сервер канала в редакторе:** после победы probe перенести протокол в
   `terrain_editor` — мир из состояния редактора, объекты (13), курсор (25), приём
   камеры (6) и рельефа (28) с **зеркалированием высот в редактор**; отправка
   изменений (объекты/рельеф) в живой Buldozer.
3. Рельеф от движка (28) — зеркалить; своих высот у TB не бывает (в TB рельеф не
   правят) — проверить, принимает ли движок наши 28; если нет — мост `buldozer.c` + F10.
4. Прогонять тесты: `py -3 -m pytest TerrainEditorPy/tests`.

## Прочее

* **Ветку прошлого сеанса в новом клоне не искать** — её локальные коммиты не
  переносятся. Всё нужное пишется заново и сливается в `main` через PR.
* Результат каждого сеанса должен попадать **в `main`** (PR + merge): пользователь
  забирает результат архивом, веток он не видит.
* Дампы (`*.log`, `captures/`, `probe_*.log`) в git не коммитить — см. `.gitignore`
  в `tools/buldozer_pipe/`.
* Метка свежести `TOOL_VERSION` лежит в `frida_capture.py`, `probe_pipe.py`, `handle_names.py` и `buldozer_channel.py`
  (даты обязаны совпадать — это проверяет тест): при обновлении инструментов
  обновляйте дату в обоих файлах.
